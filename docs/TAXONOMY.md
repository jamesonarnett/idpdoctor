# idpdoctor failure taxonomy

Generated from `internal/finding/codes.go` by `go generate ./...`; do not edit by hand.

Kind: **D** = deterministic from the artifact alone; **D+C** = deterministic once the expected value is supplied; **C** = needs config or symptom context. Mutator names the `internal/fixture` function that produces the class (blank = not yet covered by a fixture).

## Security-posture codes (lane: posture)

These fire when the artifact validates (or would under the SP settings in `expected`) yet exhibits an unsafe property.

| Code | Proto | Tier | Signal | Fix | Source | Mutator |
|---|---|---|---|---|---|---|
| `POSTURE_UNSIGNED_ASSERTION_ACCEPTED` | SAML | v0 | expected.require_signed_assertion == false, or absent while the artifact carries only a Response signature over an unsigned assertion | Require a signed assertion on the SP (and keep response signing); an unsigned assertion inside a signed response is still safe only if the SP consumes nothing outside the verified element. | OWASP SAML cheat sheet; crewjam CVE-2022-41912 class | `posture_unsigned_assertion` |
| `POSTURE_EMBEDDED_KEY_TRUST` | SAML | v0 | No idp_cert_pem / metadata supplied, so the only key available is the one inside KeyInfo; a validator that passes this way trusts the sender's key | Configure the IdP signing certificate (from metadata) on the SP and verify against it; never trust the certificate embedded in the message. | RFC 8725 3.10 analogue (jwk/jku/x5u); goxmldsig requires store roots | `posture_embedded_key` |
| `POSTURE_EXPIRED_CERT_ACCEPTED` | SAML/CERT | v0 | Signature verifies and signing cert notAfter < now | Rotate the IdP signing certificate and configure the SP to reject expired signing certificates. | Okta KB: expired IdP certs still accepted by some SPs | `posture_expired_cert` |
| `POSTURE_DECRYPT_BEFORE_VERIFY` | SAML | v0 | EncryptedAssertion present and the Response is unsigned, so an SP must decrypt before it can verify anything | Have the IdP sign the Response (or the assertion before encrypting) so the SP can verify a signature before decrypting. | Spring Security CVE-2026-41694 |  |
| `POSTURE_PARSER_DIFFERENTIAL_EXPOSURE` | SAML | v0 | DOCTYPE or entity declarations, comment nodes inside identity-bearing elements, duplicate attributes, or unusual encodings | Reject DOCTYPE and entity declarations before parsing, strip or reject comments inside NameID and AttributeValue, and use one parser for both verification and extraction. | GitHub CVE-2025-25291 / 25292; Duo PSA-2017-003 | `posture_comment_in_nameid` |
| `POSTURE_WEAK_ALGORITHM` | SAML/JWT | v0 | RSA-SHA1 signature or SHA-1 digest, RSA key < 2048 bits, HS* id_token | Move the IdP application to RSA-SHA256 with a 2048-bit or larger key; for OIDC, prefer RS256/ES256 id_tokens. | overlaps CERT_EXPIRED_OR_WEAK; posture lane when it still verifies | `posture_sha1` |
| `POSTURE_VALIDITY_WINDOW_TOO_LONG` | SAML/JWT | v0 | Assertion window > 10 minutes; SessionNotOnOrAfter > 24 hours; id_token exp - iat > 1 hour | Shorten the IdP's assertion and token lifetimes; fix clock skew with NTP instead of widening validity windows. | widening windows is the classic bad fix | `posture_long_window` |
| `POSTURE_PKCE_PLAIN_OR_ABSENT` | OAuth | v1 | Public client using code_challenge_method=plain or no PKCE at all | Use PKCE with S256 on every public client (and on confidential clients too; it is cheap). | RFC 7636 4.2 |  |
